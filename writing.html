How the scoring works

STEP 01

Classify before scoring

The model must first decide whether the prompt proposes an action (XY) or asserts a relationship (XYZ), and justify it with keywords from the question. Scoring is blocked until that step is written.

STEP 02

Apply the descriptors

The four public band descriptors (5–8) are injected into the prompt verbatim. Each criterion receives an integer band plus the reason it is not the band above, citing the candidate's own text.

STEP 03

Constrain the output

One JSON schema, no prose allowed. That keeps the report machine-readable: the interface renders nine sections from fields, and every error must quote a fragment that exists in the essay.

STEP 04

Degrade gracefully

With no API key the page falls back to a pre-generated report and a local rule-based assistant, so the demonstration never depends on a network call succeeding.

Design decisions

  • Static, but not dumb. The scoring engine is a prompt plus a schema, not a service. The whole app is three files on GitHub Pages.
  • Bring your own key. Any OpenAI-compatible endpoint works, and the key never leaves localStorage. No proxy, no shared quota, no server to fund.
  • Demo mode is first-class. Two complete reports are pre-generated, because a reviewer will not apply for an API key to look at a student project.
  • Evidence over verdicts. Every band carries a “why not the band above” sentence, and every error row quotes the original wording.
