Project Background

Built originally as a personal IELTS preparation tool, this project converts a structured question bank — 64 topics from the current IELTS Speaking syllabus — into an interactive product for listening and shadowing practice.

It is also a deliberate exercise in web engineering: the whole product is hand-written in HTML, CSS and vanilla JavaScript, while the audio is produced by a neural text-to-speech pipeline and assembled with Python and ffmpeg.

Goals

  • Deliver all 64 topics as accurate, natural-sounding practice tracks.
  • Demonstrate data-driven rendering, media control and state persistence in a real application.
  • Run fully offline and deploy anywhere as a static site.

The hard part: knowing when each line is spoken

Producing the audio is the easy half. A neural text-to-speech model will read a twelve-minute script in one pass, but the result is a single opaque waveform: the browser knows how many seconds have elapsed, not which question is playing. Cutting the script into one file per line would solve that and destroy the exercise, because practice depends on hearing the examiner's question followed immediately by the candidate's answer.

The solution is forced alignment: keep one continuous track, then recover the timings afterwards. The script is synthesised chunk by chunk so every chunk maps to a known range of lines; the assembled track is then passed through a speech recogniser that returns word-level timings. Matching that recognised word sequence back onto the known script converts a flat waveform into a list of [start, end] pairs — precisely what the player needs in order to jump to a line.

Everything downstream is cheap: the page renders from JSON, and a click sets audio.currentTime to the start of the matching pair. No database, no server, no hand-written cue points, and no risk of a timestamp drifting out of sync when the audio is regenerated.

Limitation 01

Alignment inherits the recogniser's mistakes

The script is known in advance, so a mis-heard word is usually recovered by sequence matching. When it is not, the click target shifts by a second or two — and it fails quietly. Every topic was spot-checked by ear for exactly this reason.

Limitation 02

Audio is pre-generated, not on demand

Editing a script means re-synthesising and re-aligning that topic, and a full rebuild takes hours. That trade is worth it for a fixed curriculum, where it buys a page that opens instantly — and wrong for arbitrary text, which would need synthesis at request time.

Limitation 03

It plays, but it cannot listen

The page can highlight a line and repeat it, but it cannot hear the learner. Shadowing stays self-assessed. Running the same recogniser over a microphone recording is the obvious next step, and the only one that turns this from playback into feedback.
